# write-article — เขียนบทความ blog เป็น draft

ทำหน้าที่ผลิต **draft บทความ SEO ไทย** ลงระบบ (สถานะ `pending_review`) ให้เจ้าของรีวิว/ใส่รูป/อนุมัติเอง
**ห้าม publish · ห้ามใส่รูป · เว้นช่องรูปว่างไว้**

## ขั้นตอน (ทำตามลำดับ)

### 1. เลือกหัวข้อ
- อ่าน `content/topics.md` → หยิบหัวข้อ **บนสุดที่ยังเป็น `- [ ]`**
- ถ้าผู้ใช้ระบุหัวข้อเองมาใน args → ใช้อันนั้นแทน
- ถ้าคิวหมด → แจ้งผู้ใช้ว่าหมดคิว ขอหัวข้อใหม่ อย่าเดาเอง

### 2. ค้นข้อมูลจริงก่อนเขียน (บังคับ)
- ใช้ **WebSearch** หา: ราค่ารับซื้อ/มือสองล่าสุดของรุ่นที่เกี่ยวข้อง, ข้อเท็จจริง/สเปค, บริบทพื้นที่ (แลนด์มาร์ก/ย่านในรังสิต–ปทุมธานี)
- **อย่าแต่งตัวเลข/ข้อเท็จจริงขึ้นเอง** — ถ้าไม่มั่นใจให้พูดกว้างๆ หรือชี้ไปหน้าประเมินราคาแทนการระบุเลขลอยๆ
- เช็กราคาจริงจากเว็บ khaiphone (หน้า /sell) ได้ถ้าต้องอ้างอิง

### 3. เขียนบทความ
**โทน:** สะอาด พรีเมียม ให้ข้อมูลก่อน ขายทีหลังแบบนุ่มนวล
- ❌ ห้าม: ตัวพิมพ์ใหญ่ตะโกน, "ดีที่สุดในโลก/อันดับ 1", เร่งเร้าปลอมๆ, ยัดคีย์เวิร์ดถี่ๆ, เครื่องหมายตกใจรัวๆ
- ✅ เอา: ตอบคำถามจริงของคนอ่าน → แล้วค่อยชวนไป "ประเมินราคาฟรี" แบบพอดี

**โครงสร้าง SEO (H hierarchy):**
- H1 = `title` (1 อันเท่านั้น)
- H2 = block `heading` (หัวข้อหลัก 3–6 อัน)
- H3 = block `subheading` (หัวข้อย่อยใต้ H2 ตามเหมาะ)
- ใส่: ตารางเปรียบเทียบ (`table`) 1 อันถ้าเข้าเรื่อง, ลิสต์ (`list`) 1–2 อัน, กล่องเน้น (`callout`) 1–2 อัน (มักใช้ชวนประเมินราคา), **FAQ 4–6 ข้อ** (ได้ FAQ schema)
- **คีย์เวิร์ดพื้นที่ รังสิต/ปทุมธานี** สอดเข้าเนื้อหาอย่างเป็นธรรมชาติ (title, ย่อหน้าแรก, H2 อย่างน้อยหนึ่ง, FAQ)
- เว้น **ช่องรูปว่าง 1–2 จุด** ที่ควรมีภาพ: block `image` โดย `src: ""` + ใส่ `alt` อธิบาย (ดีต่อ SEO) — เจ้าของอัปโหลดรูปทีหลัง

**meta:**
- `metaTitle` ≤ ~60 ตัวอักษร มีคีย์เวิร์ดหลัก
- `metaDescription` ≤ ~155 ตัวอักษร ชวนคลิก มีคีย์เวิร์ด
- `keywords` 5–8 วลี รวมวลีพื้นที่
- `slug` อังกฤษ-ขีดกลาง สื่อความ ไม่ซ้ำของเดิม (เช่น `buy-iphone-rangsit`)

### 4. บันทึกเป็น draft
เขียน JSON ตาม schema ด้านล่างลงไฟล์ชั่วคราวในสcrатchpad แล้วรัน:
```bash
node scripts/insert-article.mjs <path-to-article.json>
```
สคริปต์จะ insert เป็น `pending_review` โดย `hero_image = null` (ไม่มีรูป) ให้เอง

### 5. อัปเดตคิว
ใน `content/topics.md` ย้ายหัวข้อที่เขียนแล้วเป็น `- [x] หัวข้อ (slug: ...)` ไปหมวด "เขียนแล้ว"

### 6. รายงานผู้ใช้
บอก id/slug + ลิงก์ `/admin/articles` ให้ไปรีวิว/ใส่รูป/อนุมัติ · **อย่าอ้างว่า published** (มันเป็นแค่ draft)

## JSON schema ที่ต้องผลิต

```json
{
  "slug": "buy-iphone-rangsit",
  "title": "รับซื้อ iPhone รังสิต ...",
  "excerpt": "สรุปย่อ 1–2 ประโยค ...",
  "category": "วิธีขาย",
  "readTime": "5 นาที",
  "displayDate": "14 กรกฎาคม 2569",
  "articleDate": "2026-07-14",
  "keywords": ["รับซื้อ iPhone รังสิต", "ขาย iPhone ปทุมธานี", "..."],
  "metaTitle": "รับซื้อ iPhone รังสิต–ปทุมธานี | Khaiphone",
  "metaDescription": "...",
  "content": [
    { "type": "paragraph", "text": "ย่อหน้าเปิด มีคีย์เวิร์ดพื้นที่ ..." },
    { "type": "callout", "text": "ประเมินราคาฟรีที่หน้าแรก ..." },
    { "type": "heading", "text": "หัวข้อ H2" },
    { "type": "subheading", "text": "หัวข้อย่อย H3" },
    { "type": "paragraph", "text": "..." },
    { "type": "list", "items": ["ข้อ 1", "ข้อ 2"] },
    { "type": "image", "src": "", "alt": "อธิบายรูปที่ควรมีตรงนี้", "caption": "" },
    { "type": "table", "headers": ["หัวข้อ", "ก", "ข"], "rows": [["แถว", "ค่า", "ค่า"]] },
    { "type": "faq", "items": [{ "q": "คำถาม?", "a": "คำตอบ" }] }
  ]
}
```

## ข้อห้ามเด็ดขาด
- ❌ **ห้าม publish / ห้ามแตะสถานะเป็น published** — บันทึกได้แค่ `pending_review` (สคริปต์บังคับให้อยู่แล้ว)
- ❌ **ห้ามใส่ URL รูปจริง** — `image.src` และ hero ต้องว่าง (`""` / null)
- ❌ ห้ามทับหัวข้อ/ slug กับบทความเดิมใน `lib/blogData.ts`
- ❌ ห้ามแต่งราคา/ข้อเท็จจริงที่ไม่ได้ค้นเจอจริง

## ทำทีละบทความ
ต่อการสั่ง 1 ครั้ง = 1 บทความ (หยิบหัวข้อบนสุด) เว้นแต่ผู้ใช้บอกให้ทำหลายหัวข้อ
