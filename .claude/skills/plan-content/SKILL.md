# plan-content — วางแผนหัวข้อที่ดึงลูกค้าได้มากสุด

หน้าที่: เสนอ **หัวข้อบทความจัดอันดับตามศักยภาพดึงลูกค้า** ลง `content/topics.md` ให้ `/write-article` หยิบไปเขียน
เป้าหมายไม่ใช่ "ยอด traffic" อย่างเดียว แต่คือ **traffic ที่กลายเป็นลูกค้าที่มาขายเครื่องจริง**

## ขั้นตอน

### 1. ดูสิ่งที่มีแล้ว (กันทำซ้ำ)
- อ่าน slug/หัวข้อทั้งหมดใน `lib/blogData.ts` (บทความ static เดิม)
- ดึงบทความใน DB (`node scripts/list-articles.mjs` หรือ query table `articles` select slug,title,status)
- หัวข้อใหม่ **ห้ามทับ** ของเดิม (กัน keyword cannibalization)

### 2. ค้นดีมานด์จริง (บังคับ — อย่าเดา)
ใช้ **WebSearch** หา:
- คำค้นที่คนใกล้ขายเครื่องใช้ (เช่น "ขาย iPhone ที่ไหนดี", "ราคารับซื้อ iPhone [รุ่น]", "รับซื้อ [product] [พื้นที่]")
- คำถามที่คนถามบ่อย (People also ask / กลุ่ม Facebook / Pantip) เกี่ยวกับการขาย Apple มือสอง
- รุ่นที่กำลังมีคนขายเยอะ/ราคาขยับ (รุ่นใหม่ออก → คนขายรุ่นเก่า)
- คู่แข่งในพื้นที่รังสิต/ปทุมธานี rank ด้วยหัวข้ออะไร

### 3. จัดอันดับตาม "ศักยภาพดึงลูกค้า" (Acquisition Score)
ให้คะแนนแต่ละหัวข้อ (รวมแล้วเรียงมากไปน้อย):

| ปัจจัย | น้ำหนัก | เหตุผล |
|---|---|---|
| **Buy-intent (ใกล้ตัดสินใจขาย)** | สูงสุด | "รับซื้อ/ขาย/ราคารับซื้อ/ที่ไหนดี" = คนพร้อมขาย ปิดการขายได้เลย · ดีกว่าหัวข้อให้ความรู้ลอยๆ |
| **Local (รังสิต/ปทุมธานี/ลำลูกกา/ธัญบุรี/ดอนเมือง)** | สูง | จุดแข็งร้าน + คู่แข่งน้อย + rank ง่ายกว่าคำกว้าง + ลูกค้าในพื้นที่ = นัดรับถึงที่ได้จริง |
| **ช่องว่าง (ยังไม่มีในเว็บ)** | สูง | ไม่แย่ง keyword กันเอง + ครอบคลุมกว้างขึ้น |
| **ดีมานด์จริง (มีคนค้นจริง)** | กลาง | จากผลค้นเว็บ ไม่ใช่เดา |
| **Rank ได้ (long-tail เจาะจง)** | กลาง | คำเจาะจง/ยาว แข่งน้อย โอกาสติดหน้า 1 สูง |
| **เชื่อมสู่ประเมินราคา** | กลาง | หัวข้อที่จบด้วย "เช็กราคา/ประเมินฟรี" ได้เนียน = คอนเวิร์ตดี |

**ลำดับความคุ้มโดยทั่วไป:** `[รับซื้อ/ขาย product + พื้นที่]` > `[ราคารับซื้อ product ล่าสุด]` > `[ขาย product ที่ไหนดี/เทียบ]` > `[แก้ข้อกังวล เช่น จอแตก/ติด iCloud ขายได้ไหม]` > `[ให้ความรู้ทั่วไป]`

### 4. เขียนคิว
เขียนหัวข้อลง `content/topics.md` หมวด "รอเขียน" **เรียงจากคะแนนสูงสุดลงมา** (บนสุด = คุ้มสุด)
แต่ละหัวข้อใส่เหตุผลสั้นๆ ต่อท้ายเป็น comment ว่าทำไมคุ้ม (intent/local/gap)

### 5. รายงาน
สรุปให้ผู้ใช้: เสนอกี่หัวข้อ, 3 อันดับแรกคืออะไรและทำไมคุ้มสุด, อ้างอิงแหล่งค้นเว็บ
**อย่าเขียนบทความในสกิลนี้** — แค่วางแผนคิว ให้ `/write-article` เขียนต่อ

## Local area series — บทความ "รับซื้อ [product] [พื้นที่]" ครบทุกเขต กทม.+ปริมณฑล
เป้าหมาย: ครอบคลุมทุกพื้นที่ (แบบ `buy-iphone-rangsit`) — buy-intent + local = คู่แข่งน้อย ปิดการขายได้จริง

**⚠️ กฎเหล็กกัน doorway/thin-duplicate (Google ลงโทษ):** ห้ามทำแค่สลับชื่อเขตในเทมเพลตเดียว
แต่ละหน้าพื้นที่ **ต้องมีเนื้อหาท้องถิ่นจริงที่ไม่ซ้ำกัน** อย่างน้อย:
- แลนด์มาร์ก/ห้าง/ตลาด/สถานี BTS-MRT/มหาลัย ของย่านนั้นจริงๆ (เช่น รังสิต→ฟิวเจอร์พาร์ค, บางกะปิ→เดอะมอลล์, ลาดกระบัง→สนามบิน/สจล.)
- บริบทเฉพาะย่าน (รถติดตรงไหน, ย่านหอพัก/ออฟฟิศ/คอนโด, เส้นทางที่ทีมงานเข้าถึง)
- FAQ ที่อ้างพื้นที่นั้นจริง + ย่อหน้าเปิด/H2 ที่พูดถึงพื้นที่แบบเจาะจง

**จัดลำดับพื้นที่ตามศักยภาพ:**
1. **โซนรับถึงที่ฟรี ใกล้ฐาน** (ปทุม/ดอนเมือง/สายไหม/บางเขน/หลักสี่/ลำลูกกา/ธัญบุรี/คลองหลวง) — บริการได้ดีสุด นัดรับถึงที่จริง = คอนเวิร์ตสูงสุด
2. **โซนฟรีอื่นในกทม.+ปริมณฑล** (เทียบ `lib/zones.ts` — core zone)
3. โซนไกล/เข้ารับเป็นรอบ (ชลบุรี/ฉะเชิงเทรา) — ทำทีหลัง
- เชื่อมทุกหน้าเข้าหน้า **ประเมินราคาฟรี** + ลิงก์ข้ามพื้นที่ใกล้กัน (internal link)

**⏱️ Phased rollout (สำคัญ):** อย่า publish 50 หน้ารวดเดียว — Google จับ pattern content ทะลักเป็นสัญญาณ spam
ทยอยอนุมัติ **ไม่กี่หน้า/สัปดาห์** จากโซนใกล้ฐานก่อน แล้วค่อยขยายออก

## หลักคิดสำคัญ
- **คุณภาพ > ปริมาณ** — แต่ละหน้าต้องมีคุณค่า/เนื้อหาท้องถิ่นจริง ไม่ใช่ก็อป
- อย่าเสนอหัวข้อที่ rank ไม่ได้ (คำกว้างเกิน แข่งกับ apple.com) หรือไม่มี buy-intent
- ให้ผู้ใช้เลือก/ปรับได้ — นี่คือ "ข้อเสนอ" ไม่ใช่คำสั่งตายตัว
